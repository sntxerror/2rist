## Ключевые механизмы

### Линейная привязка (LRS)

`geo.RouteIndex` держит маршрут как `LineString` в азимутальной
равнопромежуточной проекции с центром на самом маршруте — расстояния и буферы
считаются в метрах без выбора UTM-зоны. Любая точка проецируется на линию
и получает `(s — метры от старта, offset — метры от оси, side — сторона
по ходу движения)`. Сторона определяется знаком векторного произведения
направления движения на вектор к объекту.

Это превращает список в аудиогид: клиент показывает карточку по мере
продвижения, а не вываливает всё сразу.

### Коридор

Радиус зависит от профиля: пешком 250 м, велосипед 400 м, машина 1200 м.
На маршрутах длиннее 50 км радиус растёт — на трассе с коридором в 250 м
не найдётся ничего.

Запрос к Overpass идёт **bbox-чанками по 4 км** (`sources.route_bboxes`),
потому что `around` вдоль длинной ломаной публичный Overpass не переживает.
Лишнее из углов bbox отсекается локально проверкой `offset <= radius * 1.25`.

### Склейка источников

Один памятник приходит из OSM, Wikidata и Википедии под разными именами
и с разными координатами.

1. Совпал QID — это один объект, вопросов нет. QID берётся из тега OSM
   `wikidata` и из `pageprops.wikibase_item` Википедии.
2. Иначе — пространственный поиск (`shapely.STRtree`, до 70 м) плюс похожесть
   имени (`rapidfuzz.token_set_ratio`, порог 0.62). Перед сравнением из имён
   вырезаются родовые слова: «Памятник Пушкину» и «Пушкину, памятник» — одно.
3. Слияние по приоритету: геометрия из OSM, значимость и факты из Wikidata,
   тексты и картинки из Википедии.

### Скоринг

```
score = 0.34·notability + 0.18·class + 0.14·proximity
      + 0.12·heritage + 0.12·liveliness + 0.10·interest
```

- `notability` — `log1p(sitelinks) / log1p(60)`, число языковых версий
  Википедии. Слабое место, см. открытые вопросы.
- `class` — вес класса объекта из таксономии: крепость 0.85, придорожный
  крест 0.3.
- `proximity` — насколько близко к оси маршрута.
- `heritage` — охранный статус (ЮНЕСКО, федеральный, региональный).
- `liveliness` — полнота тегов: сайт, телеграм, часы работы, свежий
  `check_date`. Это единственный сигнал для мест без Википедии.
- `interest` — совпадение с выбранными пользователем категориями.

### Разрежение и квоты

Без разрежения весь топ-30 оказывается в историческом центре, а остальные
километры пустые. Маршрут делится на отрезки, из каждого берётся лучшее.

Поверх этого две квоты:

- **Современный слой** — 40% выдачи (`rank.MODERN_SHARE`). Без неё места без
  статьи в Википедии не всплывают никогда.
- **Потолок на категорию** — 30% (`rank.CATEGORY_CAP`). Мемориальных досок
  на улице бывает десяток подряд, и они вытесняют всё остальное.

### Две стадии

- `stage=fast` — только OSM и Википедия, значимость **только из кэша**
  (`only_if_cached`), без SPARQL и районов. Черновик за 2-4 с.
- `stage=full` — плюс события Wikidata, районы, «настроение».

Запрос к Overpass у обеих стадий **байт в байт одинаковый**, поэтому полная
стадия берёт его из кэша, а не ходит в сеть второй раз. Фронтенд рисует
черновик и заменяет его полным ответом.

### Настроение районов

`vibe.py` считает то, что в Hoodmaps размечают вручную. Каждое заведение
в коридоре даёт сигнал с весом: бар — «ночная жизнь» 1.4, университет —
«студенты» 1.6, полигон промзоны — «промзона» 3.0. Вес падает с удалением
от маршрута. По отрезкам (границы районов либо ровные бины) считаются доли,
наверх выводятся три сильнейших с долей от 12%.

### AI-слой

Протокол из двух шагов, потому что смешивать инструмент поиска и строгую
JSON-схему в одном вызове Gemini нельзя:

1. `research` — вызов с `google_search`, модель ищет и отвечает текстом,
   API возвращает grounding-метаданные со ссылками.
2. `structure` — вызов без инструментов, но с `responseSchema`, тот же текст
   раскладывается в строгий JSON.

Защита от выдумок:

- на вход подаются только проверенные факты (координаты, адрес из обратного
  геокодирования, год, тип, описание из Wikidata) — модель не угадывает,
  о чём речь;
- сюжет без источника из grounding-метаданных выбрасывается;
- непроверенное уходит в `unverified` и в интерфейсе помечается как
  требующее проверки;
- сюжеты ранжируются по типу: человек и «что было раньше» важнее, чем
  «отсюда красивый вид», которое модель выдаёт с уверенностью 0.9.

## API

```
POST /api/route-highlights   маршрут → объекты, районы, настроение
                             (stage=fast|full)
GET  /api/poi                подробности объекта (+ai=1 — AI-исследование)
GET  /api/suggest            подсказки адресов
GET  /api/whereami           страна и центр по IP
GET  /api/poi-address        обратное геокодирование точки
GET  /api/categories         словарь категорий
```

## Транспорт и кэш

`app/http.py` — одна сессия на всё: `requests-cache` (SQLite, TTL 14 дней)
поверх `requests-ratelimiter`. Отдельная сессия с лимитом 1 запрос/с для
Nominatim, у которого это жёсткое правило.

Куки отключены намеренно: Википедия отдаёт `Vary: Cookie` и ставит куки
на первом же ответе, из-за чего второй запрос уходит с другими заголовками
и мимо кэша.

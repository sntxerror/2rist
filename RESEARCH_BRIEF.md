# 2rist — задачи, блокеры, ресёрч

Состояние на 2026-07-28. Сервис работает на реальных данных, узкое место —
сетевые задержки публичных API в горячем пути.

## Измерено

| Источник | Холодный запрос | Комментарий |
|---|---|---|
| Wikidata SPARQL (WDQS) | 12–30 с | главный тормоз |
| Overpass | 6–10 с | лимит 2 слота на клиента, ходим по одному |
| Wikipedia API | ~2 с | приемлемо |
| Nominatim + OSRM | 1–2 с | приемлемо |
| Собственная обработка | <0.5 с | не проблема |

Итого: холодный маршрут 9–35 с, повторный из кэша 1.5 с.
Цель: **1–2 с без кэша**.

## Блокеры

**Б1. WDQS в горячем пути.** Публичный сервис даёт 12–30 с и таймауты на
части батчей («обогащено 26 из 28»). Пока он там, целевые 1–2 с недостижимы.
Снимается только локальной таблицей значимости.

**Б2. Overpass — общий ресурс.** Лимит слотов, 429/504 при параллельных
запросах. Сейчас обходим очередью и ожиданием слота, но это потолок.
Снимается локальным инстансом или переходом на Overture/PostGIS.

**Б3. Нет офлайн-данных вообще.** Любой новый регион = холодный запрос ко
всем четырём источникам. Пока не выбран формат локального хранилища,
слои 3–4 (популярность, предрасчёт) делать не на чем.

**Б4. Качество значимости.** Ранжируем по числу языковых версий Википедии.
Это меряет энциклопедическую известность, а не реальный интерес: проходной
особняк и Патриаршие пруды получают близкий скор. Нужны просмотры страниц.

## Задачи (в порядке отдачи)

1. **Локальная таблица Wikidata.** `qid → sitelinks, coords, P31, P571, P84,
   P149, P1435, label(ru/en)`. Источник — `latest-truthy.nt.gz`, фильтр по
   наличию P625. Выход — parquet, читается duckdb. Минус 12–30 с.
2. **Локальный источник OSM.** Выбрать из трёх: Overture через duckdb (без
   импорта), Overpass в докере, osm2pgsql flex → PostGIS. Минус 6–10 с.
3. **Просмотры страниц вместо sitelinks** в скоринге значимости.
4. **Новые слои данных** (см. ниже) — мемориальные доски, этимология улиц,
   P551/P937, PastVu.
5. **Предрасчёт по H3-ячейкам** — финальная форма, запрос = spatial join.

## Вопросы ресёрча

**Р1. Wikidata без парсинга 40 ГБ.** Существуют ли готовые срезы items
с координатами (P625) в parquet/csv? Кандидаты: Kensho Derived Wikimedia
Dataset, wikidata-geo, Sophox, DBpedia. Нужны: актуальность, размер, лицензия,
есть ли sitelinks. Если готового нет — сколько времени и диска займёт
стриминговый парсинг truthy-дампа на 8 ядрах.

**Р2. Overture Maps как замена Overpass.** Покрытие `places` и `buildings`
в Тбилиси и Москве против OSM: сколько объектов нашего профиля (памятники,
храмы, музеи, инженерные сооружения) реально есть. Скорость bbox-запроса
к S3-parquet через duckdb. Есть ли связь с Wikidata QID.

**Р3. PastVu API** (исторические фото с координатами) — лимиты, лицензия,
формат ответа, покрытие вне Москвы и Петербурга.

**Р4. Просмотры Wikipedia.** Pageviews API против месячных дампов: что
дешевле для 10–50 тысяч статей на регион, какие лимиты.

**Р5. Платные Places API** на случай нехватки открытых данных по современной
культуре: Foursquare, Geoapify, Google Places. Бесплатные лимиты, стоимость,
разрешено ли кэширование (у Google — нет, это принципиально).

**Р6. Охранные реестры.** ОКН Минкультуры (opendata.mkrf.ru) — жив ли
и в каком формате. Аналог для Грузии.

## Ограничения, найденные опытом

- Overpass не переваривает `around` вдоль длинной ломаной (504) — только bbox.
- Параллельные запросы к Overpass дают 429; ходить строго по одному
  и спрашивать `/api/status`.
- requests-cache не кэширует Wikipedia, пока не отключены куки: `Vary: Cookie`.
- Полные факты Wikidata для сотен объектов — десятки секунд, поэтому они
  грузятся лениво, по одному объекту при открытии карточки.

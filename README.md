# 2rist

Сервис: на вход — маршрут, на выходе — упорядоченный по километражу список
знаковых мест вдоль него, с культурной, исторической, социальной и инженерной
точки зрения. Плюс районы, которые маршрут пересекает, и их «настроение».

Все базовые источники — открытые и бесплатные, без ключей. Ключ нужен только
для необязательного AI-слоя.

## Запуск

```bash
./run.sh
```

Откроется на http://127.0.0.1:8080 — карта, точки маршрута A→B→C, лента объектов.

Зависимости уже стоят в `.venv`; поставить заново: `pip install -r requirements.txt`.

## Как это устроено

```
маршрут → коридор → 4 источника → склейка → ранжирование → разрежение → ответ
                                              ↓ по клику
                                    подробности + AI-исследование
```

| Модуль | Отвечает за |
|---|---|
| `app/geo.py` | линия маршрута в метрической проекции, километраж, сторона, коридор (shapely + pyproj) |
| `app/sources.py` | OSRM, Nominatim, Overpass, Wikidata SPARQL, Wikipedia |
| `app/merge.py` | нормализация и склейка дублей (QID → пространство + rapidfuzz) |
| `app/taxonomy.py` | теги OSM и типы Wikidata → смысловые категории |
| `app/rank.py` | скоринг значимости и разрежение по километражу |
| `app/vibe.py` | «настроение» участков по составу заведений |
| `app/narrate.py` | районы вдоль маршрута, привязка объекта к месту |
| `app/ai.py` | люди, события, что было раньше, этимология улицы (Gemini + поиск) |
| `app/pipeline.py` | сборка всего перечисленного |
| `app/api.py` | HTTP-API на FastAPI |

### Почему именно так

**Линейная привязка вместо радиуса.** Каждый объект проецируется на линию
маршрута и получает `(км от старта, отступ в метрах, сторона по ходу)`. Это
превращает список в аудиогид: клиент показывает карточку по мере продвижения.

**Значимость из Wikidata.** Число языковых версий Википедии (`wikibase:sitelinks`)
— лучший бесплатный прокси известности. Плюс охранный статус (P1435).

**Разрежение обязательно.** Без него весь топ-30 оказывается в историческом
центре, а остальные километры пустые. Маршрут делится на отрезки, из каждого
берётся лучшее.

**Дорогое — лениво.** Полные факты Wikidata и тексты Википедии для сотен
объектов стоят десятки секунд. Список отдаёт лёгкие карточки, подробности
приходят по `/api/poi` при открытии объекта.

**Overpass строго по одному запросу за раз.** У публичных инстансов лимит
слотов; параллельные выборки дают 429/504 и ретраи на минуты. Перед запросом
спрашиваем `/api/status` и ждём слот. POI и фон для «настроения» забираются
одной выборкой и делятся локально (`sources.is_poi`).

## API

```
POST /api/route-highlights   маршрут → объекты, районы, настроение
GET  /api/poi                подробности объекта (+ai=1 — AI-исследование)
GET  /api/suggest            подсказки адресов
GET  /api/whereami           страна и центр по IP
GET  /api/poi-address        обратное геокодирование точки
GET  /api/categories         словарь категорий
```

Пример:

```bash
curl -X POST localhost:8080/api/route-highlights -H 'Content-Type: application/json' -d '{
  "route": {"from": "площадь Свободы, Тбилиси", "to": "Мост Мира, Тбилиси", "profile": "walking"},
  "limit": 20,
  "interests": ["architecture", "infrastructure"]
}'
```

Маршрут можно задать четырьмя способами: `from`/`to`/`via` (адреса),
`points` (координаты), `polyline` (готовая линия), `geojson` (LineString).

## AI-обогащение

Отвечает на то, чего нет в справочниках: кто здесь жил, что случилось, что
было на этом месте раньше, откуда название улицы.

Протокол из двух шагов (смешивать поиск и JSON-схему в одном вызове Gemini
нельзя): грounded-вызов с `google_search` → структурирование по `responseSchema`.

Защита от выдумок: на вход подаются только проверенные факты об объекте;
сюжет без источника из grounding-метаданных выбрасывается; неподтверждённое
уходит в `unverified` и помечается в интерфейсе как требующее проверки.

Ключ читается из `.env` (`GEMINI_API_KEY=…`), файл в `.gitignore`.
Дневной потолок вызовов — `TRIST_AI_DAILY_LIMIT` (по умолчанию 300).

## Скорость

Холодный запрос по городскому маршруту — 9–35 c, повтор из кэша — 1–2 c.
Кэш HTTP на SQLite лежит в `data/cache/`, живёт 14 дней.

Узкое место — публичные Overpass и WDQS. Для продакшена:

1. **Свой Overpass или PostGIS** из выгрузки Geofabrik — запросы уходят
   в доли секунды, лимитов нет. Главный шаг.
2. **Локальный OSRM** вместо демо-сервера project-osrm.org.
3. **Дамп Wikidata** или собственный кэш значимости по QID.

Тогда весь пайплайн укладывается в 1–2 c без кэша.
